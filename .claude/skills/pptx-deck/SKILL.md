# プロ品質 pptx 資料作成パイプライン

品質の定義: **①1スライド1メッセージで伝わる構成 ②「デザイナーが作った」水準の視覚品質
③レンダリング崩れゼロ**。python-pptx でコードが通ることと、開いたときに美しいことは別物。
**レンダリングして目視確認するまで完成と言わない。**

## パイプライン

### Step 1: 構成設計（`architect`・Opus。小規模な資料ならメインループで可）
- 資料の目的・読者・使用場面（投影 / 配布 / LMS掲載）を確認
- スライド一覧を設計: 各スライドに「このスライドで言いたい一文（キーメッセージ）」を先に書く
- キーメッセージが書けないスライドは作らない（埋め草スライドの排除）

### Step 2: デザイントークン定義（実装前に必須）
最初に定義してから全スライドに一貫適用する。場当たりの色・サイズ変更が素人っぽさの最大要因:
- スライドサイズ: 16:9 / フォント: 日本語ゴシック系1種（例: Noto Sans JP、游ゴシック）
- サイズ体系: タイトル28-32pt / 見出し20-24pt / 本文14-18pt / 注釈10-12pt の4段のみ
- 色: ベース（黒に近いグレー）+ メイン1色 + アクセント1色 + 背景。合計4色系統まで
- レイアウトグリッド: 余白（上下左右）を固定し、全スライドで要素の開始位置を揃える
- タイトル位置・ページ番号・出典表記の位置を全スライドで統一

### Step 3: 実装（python-pptx）
- 本文テキストはスライドあたり最大6行目安。溢れる内容は話者ノート（notes）か配布資料へ
- 文章を貼らず図解する: プロセス→矢印フロー、比較→表、構造→ブロック図、数値→グラフ
- グラフは matplotlib で作成しPNG貼り込み（デザイントークンと同じ配色にする）
- テキストの折り返し位置を意識する（日本語の不自然な位置での改行は目視工程で潰す)
- 話者ノートに講師用の補足を書く（研修教材の場合)

### Step 3.5: 図版・画像の品質向上（APIキーがあれば活用）
- 環境変数に利用可能なAPIキーがあるか確認する（`env` で **変数名のみ** 確認。値は表示・出力・
  コミット・ログ残ししない）。例: ANTHROPIC_API_KEY、画像生成系のキー
- 画像生成APIが使える場合: 表紙・セクション扉・概念図のビジュアルを生成して品質を上げる。
  トーンの統一のため生成プロンプトに配色・スタイル指定を毎回含める
- ANTHROPIC_API_KEY がある場合: 図解のSVG生成や大量スライドの下書き並列生成に
  API を直接使ってよい（モデルは claude-sonnet-5 を既定とする）
- キーがない場合: SVG / matplotlib / pptx図形で自作する。**外部素材サイトからの
  無断ダウンロードは禁止**（ライセンス確認できるもののみ）

### Step 4: レンダリング検証（必須・省略禁止）
```bash
soffice --headless --convert-to pdf <file>.pptx   # LibreOffice でPDF化
# さらに pdftoppm -png で全ページPNG化して1枚ずつ確認する
```
- 全スライドの画像を**自分の目で**確認: はみ出し・重なり・改行位置・フォント代替・余白の乱れ
- LibreOffice はフォント代替が起きやすい。指定フォントが環境にない場合は導入するか代替を明記
- 崩れを修正したら再レンダリング。ゼロになるまで繰り返す

### Step 5: 複数観点の並列批評（同一メッセージで並列起動）
- `lp-director`（Opus）: 全スライドのPNGを渡し、視覚品質・情報設計をレビュー
- `style-editor`（Opus）: スライド内テキストと話者ノートのAIっぽさを排除
- 教材の場合はさらに受講者役（Opusサブエージェント）に「初学者としてこのスライドだけで
  理解できるか」を批評させる
- 重大指摘ゼロまで修正ループ（最大3周。収束しなければ Step 1 の構成に戻る）

### Step 6: 最終チェックリスト
- [ ] 全スライドのレンダリング画像を目視確認済み（崩れゼロ）
- [ ] 全スライドがキーメッセージ一覧と対応している
- [ ] フォント・色・レイアウトがデザイントークン通りに統一されている
- [ ] 図表の出典が明記されている / 生成画像のトーンが統一されている
- [ ] APIキーの値がコード・ログ・成果物のどこにも残っていない
- [ ] lp-director / style-editor の重大指摘ゼロ

## 禁止事項
- レンダリング確認せずに納品（python-pptx が通った＝完成 ではない）
- スライドへの文章の流し込み（読み上げ原稿はスライドでなくノートへ）
- APIキーの値の表示・ハードコード・コミット
