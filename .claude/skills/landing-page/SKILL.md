# プロ品質 LP/HP 制作パイプライン

品質の定義: **①ターゲットが3秒で価値を理解しCVに至る導線** と
**②「制作会社に頼んだ」水準の視覚品質・技術品質**。
コードが動くことと「プロ品質」の間には大きな差がある。差を埋めるのはレビューループ。

## パイプライン

### Step 0: ブリーフ確認（不足したまま作り始めない）
必須入力: ①目的とCV定義（問い合わせ/購入/資料DL…） ②ターゲット（誰の・どんな悩み）
③提供価値と証拠（実績・事例・お客様の声 — **実データ。捏造禁止**） ④競合・参考サイト
⑤トンマナ（ロゴ・ブランドカラー・雰囲気） ⑥公開先（ホスティング・ドメイン・フォーム送信先）。
不足があればヒアリングシートを作って質問する。**証拠素材の有無はCVRを最も左右する**ので必ず確認。

### Step 1: リサーチ（`scout` + `fact-checker`・並列起動)
- scout: 既存資産（過去のLP・素材・コンポーネント）の棚卸し
- fact-checker: 掲載予定の実績数値・比較表現の裏取り（景表法・薬機法リスクのある表現の洗い出し)

### Step 2: 構成・コピー設計（`architect`・Opus）
- ページ構成: ファーストビュー → 問題提起 → 解決策 → 証拠 → 不安の解消（FAQ・保証）→ CTA
  の流れで、セクションごとの役割とCTA配置を設計
- ファーストビューのコピー案を複数（キャッチ・サブ・CTA文言）
- 各セクション⇔ターゲットの検討段階の対応表

### Step 3: 実装（メインループ・Sonnet 5）
技術基準:
- セマンティックHTML、モバイルファーストのレスポンシブ（フレックス/グリッド、相対単位）
- デザイントークンを最初に定義（色は3色系統まで＋ニュートラル、フォントは最大2種、
  余白は8pxグリッド）— 場当たりで色やサイズを増やさない。これが「素人っぽさ」の最大要因
- 画像最適化（適切なフォーマット・遅延読み込み）、CLSを起こさない寸法指定
- メタ情報一式（title/description/OGP/favicon）、フォームのバリデーションと送信確認
- アクセシビリティ: コントラスト比 4.5:1 以上、alt、キーボード操作、フォーカス表示

### Step 4: 実機検証（メインループ・必須）
Playwright/Chromium（インストール済み）で実際に開いて確認:
- モバイル（375px）とデスクトップ（1440px）のフルページスクリーンショットを撮る
- コンソールエラー 0 件、リンク切れ・フォーム動作の確認
- ファーストビューがモバイルで成立しているか（CTAが見えるか）をスクリーンショットで目視

### Step 5: クリエイティブレビュー（`lp-director`・Opus）
ブリーフ・スクリーンショット・ソースを渡してレビューさせる。
- 「要修正」以上の指摘 → 修正して再レビュー。**最大3周**。
- 3周で「出荷可」にならなければ Step 2 の構成に戻る。

### Step 6: コードレビュー（`deep-reviewer`・Opus）
フォーム処理・外部送信・埋め込みスクリプトなど動作面の最終レビュー。
バグ修正が2回失敗したら `debugger` にエスカレーション。

### Step 7: 最終チェックリスト
- [ ] モバイル・デスクトップ両方のスクリーンショットを確認済み（ユーザーにも添付する）
- [ ] コンソールエラー 0・リンク切れ 0・フォーム送信動作確認済み
- [ ] 掲載した実績・数値はすべて実データ（出典・提供元を記録）
- [ ] 誇大表現・景表法/薬機法リスク表現なし（fact-checker の洗い出しと突き合わせ）
- [ ] lp-director「出荷可」判定済み
- [ ] OGP・メタ情報・favicon 設定済み

## 禁止事項
- スクリーンショットを撮らずに「見た目は問題ないはず」で納品すること
- 架空の実績・お客様の声の掲載（法的リスク。素材がなければユーザーに依頼する)
- lp-director レビューを通さない納品
